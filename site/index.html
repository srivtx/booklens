Auditing tools do not repair books

EPUB accessibility tooling splits into two halves that never meet. Auditing is solved: DAISY ACE reports on EPUB Accessibility 1.1 and WCAG 2.x, and EPUBCheck validates conformance. Both are maintained, offline tools.

Fixing is not. Neither writes a corrected book. The only tool that repairs content is Access-Aide, a Sigil GUI plugin that is not scriptable, cannot run in CI, and pauses for manual alt-text entry. The one project advertising a one-command fixer has no stars, no license file, and has never been published to npm.

booklens does that repair step. It audits a book and emits a repaired EPUB, so accessibility work can run in a pipeline instead of a desktop application.

  • DAISY ACE

    Reports on EPUB Accessibility 1.1 and WCAG 2.x. It audits but does not repair.

  • EPUBCheck

    Validates EPUB conformance. It says whether a book is valid, not whether it is accessible.

  • Access-Aide

    A Sigil plugin that repairs content. It is not scriptable and it stops for manual alt text.

What booklens does

booklens checks 15 rules against EPUB Accessibility 1.1 and WCAG 2.x. Everything runs locally using unzip, XML, and HTML parsing.

Audit and fix

Audits a book and writes a repaired EPUB. Audit exits 1 on any error-severity issue, so a pipeline stops on regressions.

Metadata

Adds dc:language, dc:title, and the five schema:* accessibility metas when they are missing.

Language

Sets lang and xml:lang on every spine document so assistive technology reads the correct language.

Alt text placeholders

Adds alt="" to images with no alt attribute and lists each one so a human can fill in real text.

Navigation

Adds a landmarks nav, builds a page-list when the book has pagebreaks, and generates a navigation document when the book has none.

Verification

Re-audits the result and returns the remaining issues, so a pipeline can tell fixed from fixed and verified.

Offline CLI and library

No network code. Run it from the CLI or import it as a library.

Archive writer

fixEpub always returns the best archive it can produce, and the writer places mimetype first and uncompressed as the spec requires.

How booklens works

  1. 01

    Audit

    Unzip the EPUB and run 15 rules against EPUB Accessibility 1.1 and WCAG 2.x. Output is human-readable, JSON, or SARIF.

  2. 02

    Fix

    Repair metadata, language, alt placeholders, and navigation. Apply every fix, or pass --only for a subset.

  3. 03

    Verify

    Re-audit the repaired archive and return what remains, so a pipeline can fail when a human still needs to make a judgement.

The rules that are reported but not auto-fixed are the ones where a repair would require judgement. Guessing a heading level or a link label silently corrupts the book; booklens leaves those to a human and says so.

Install booklens

# One-line install (installs the `booklens` binary)
curl -fsSL https://raw.githubusercontent.com/srivtx/booklens/main/install.sh | sh

# Or run once, without installing
bunx github:srivtx/booklens audit book.epub

# Install globally
bun add -g github:srivtx/booklens
booklens audit book.epub

# Add to a project as a dev dependency
bun add -d github:srivtx/booklens

booklens is not published to npm. Install it with the one-line script, or run it without installing.

CLI and library

# Audit: human output, exit 1 if there are any errors
bunx github:srivtx/booklens audit book.epub

# Audit: machine-readable for CI
bunx github:srivtx/booklens audit book.epub --json

# Fix: write a corrected EPUB
bunx github:srivtx/booklens fix book.epub -o book.fixed.epub --language en --title "My Book"

# Preview the fixes without writing anything
bunx github:srivtx/booklens fix book.epub --dry-run

# Apply only selected fixes
bunx github:srivtx/booklens fix book.epub --only E001,E002,W010

# Emit SARIF for GitHub code scanning
bunx github:srivtx/booklens audit book.epub --sarif booklens.sarif

Or call it as a library:

import { audit, fixEpub } from "booklens";

const report = audit(bytes, "book.epub");

if (report.counts.error > 0) {
  const { data, applied, remaining } = fixEpub(bytes, {
    language: "en",
    title: "My Book",
  });
  // data: corrected EPUB bytes, applied: changelog, remaining: re-audit issues
}

SARIF and GitHub code scanning

Audit exits 1 on any error-severity issue. Emit a SARIF 2.1.0 log and let GitHub code scanning annotate the pull request.

- run: bunx github:srivtx/booklens audit public/book.epub --sarif booklens.sarif
- uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: booklens.sarif

--fail-on controls when the command exits non-zero and defaults to error. Pass warning, info, or none to loosen it. fix accepts the same --sarif and --fail-on flags; its SARIF report describes the issues remaining after the fix.

What booklens does not do

booklens fixes metadata, language, alt placeholders, and navigation. It does not repair layout or reading order, and it does not invent alt text. PDF and Office formats are handled by sibling tools, not here.

  • It does not reconstruct reading order or layout.
  • It does not generate alt text; placeholders are marked for a human.
  • It does not handle PDF, DOCX, ODF, or SVG.

Frequently asked questions

Does my book leave my machine?

No. The CLI and the library have no network code, and the browser playground unzips and parses everything locally. Nothing is uploaded and no request is made.

What exactly gets fixed?

Missing dc:language, dc:title, and the five schema:* accessibility metas; missing lang / xml:lang; missing alt attributes as placeholders; and navigation landmarks, page-lists, or a whole navigation document.

Why are some rules reported but not fixed?

Because a repair needs judgement. Guessing a heading level or a link label can silently corrupt a book, so booklens reports those and leaves the decision to a human.

Can it run in CI and fail a pull request?

Yes. Audit exits 1 on any error-severity issue and can emit SARIF 2.1.0 for GitHub code scanning. --fail-on controls the threshold.

Does it handle other file formats?

No. booklens is EPUB only. Office, ODF, SVG, and web-archive formats are covered by its sibling tools, linked in the footer.
