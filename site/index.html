The gap it fills

Auditing is solved. Repair is not.

EPUB accessibility tooling splits into two halves that never meet. Auditing is solved: DAISY ACE reports on EPUB Accessibility 1.1 and WCAG 2.x, and EPUBCheck validates conformance. Both are excellent, maintained, offline tools.

Fixing is not. Neither writes a corrected book. The only thing that repairs content is Access-Aide, a Sigil GUI plugin: it is not scriptable, it cannot run in CI, and it pauses for manual alt-text entry. The one project advertising a one-command fixer has zero stars, no license file, and has never been published to npm.

booklens closes that half. It audits a book and emits a repaired EPUB, so accessibility work runs in a pipeline instead of a desktop application.

  • Audits · offline

    DAISY ACE

    Reports on EPUB Accessibility 1.1 and WCAG 2.x. Excellent, maintained — and reporting only.

  • Validates · offline

    EPUBCheck

    Proves EPUB conformance. Says whether a book is valid, not whether it is accessible.

  • Fixes · GUI only

    Access-Aide

    The one content repairer. A Sigil plugin: not scriptable, not CI, and it stops for manual alt text.

What it does

A small, sharp tool for one job

Everything is local unzip, XML, and HTML parsing — no service, no telemetry, no surprises.

audit → fix

Audit and fix in one pass

Audits a book and emits a repaired EPUB. Audit exits 1 on any error-severity issue, so a pipeline stops on regressions.

metadata

Metadata repair

Adds dc:language, dc:title, and the five schema:* accessibility metas when they are missing.

lang

Language everywhere

Sets lang and xml:lang on every spine document, so assistive technology reads the right language.

alt

Alt placeholders with a changelog

Adds alt="" to images with no alt attribute, and lists every one so a human can fill in real text.

nav

Navigation built for you

Adds a landmarks nav, builds a page-list when the book has pagebreaks, and generates a navigation document when the book has none.

verify

Fixed and verified

Re-audits the result and returns the remaining issues, so a pipeline can tell “fixed” from “fixed and verified”.

offline

Offline and scriptable

No network code at all. Call it from the CLI or import it as a library.

safe

Never throws

fixEpub always returns the best archive it could produce, and the writer places mimetype first and uncompressed as the spec requires.

How it works

Three moves, no ceremony

  1. 01

    Audit

    Unzip the EPUB and run 15 rules against EPUB Accessibility 1.1 and WCAG 2.x. Human output, JSON, or SARIF.

  2. 02

    Fix

    Repair metadata, language, alt placeholders, and navigation. Choose every fix, or pass --only for a subset.

  3. 03

    Verify

    Re-audit the repaired archive and return what remains, so a pipeline can fail loudly when judgement is still needed.

The rules that are reported but not auto-fixed are the ones where a repair would require judgement. Guessing a heading level or a link label silently corrupts the book; booklens leaves those to a human and says so.

Usage

CLI and library

# Audit — human output, exit 1 if there are any errors
booklens audit book.epub

# Audit — machine-readable for CI
booklens audit book.epub --json

# Fix — write a corrected EPUB
booklens fix book.epub -o book.fixed.epub --language en --title "My Book"

# Preview the fixes without writing anything
booklens fix book.epub --dry-run

# Apply only selected fixes
booklens fix book.epub --only E001,E002,W010

# Emit SARIF for GitHub code scanning
booklens audit book.epub --sarif booklens.sarif

Or call it as a library:

import { audit, fixEpub } from "booklens";

const report = audit(bytes, "book.epub");

if (report.counts.error > 0) {
  const { data, applied, remaining } = fixEpub(bytes, {
    language: "en",
    title: "My Book",
  });
  // data: corrected EPUB bytes, applied: changelog, remaining: re-audit issues
}

Continuous integration

SARIF and GitHub code scanning

Audit exits 1 on any error-severity issue. Emit a SARIF 2.1.0 log and let GitHub code scanning annotate the pull request.

- run: bunx booklens audit public/book.epub --sarif booklens.sarif
- uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: booklens.sarif

--fail-on controls when the command exits non-zero and defaults to error. Pass warning, info, or none to loosen it. fix accepts the same --sarif and --fail-on flags; its SARIF report describes the issues remaining after the fix.

Honest scope

What it will not do

Limitations

booklens fixes metadata, language, alt placeholders, and navigation. It does not do layout or reading-order repair, and it will not invent alt text. PDF and Office formats are handled by sibling tools, not here.

  • No reading-order or layout reconstruction.
  • No generated alt text — placeholders are marked for a human.
  • No PDF, DOCX, ODF, or SVG handling.

Questions

Frequently asked

Does my book leave my machine?

No. The CLI and the library have no network code, and the browser playground unzips and parses everything locally. Nothing is uploaded and no request is made.

What exactly gets fixed?

Missing dc:language, dc:title, and the five schema:* accessibility metas; missing lang / xml:lang; missing alt attributes as placeholders; and navigation landmarks, page-lists, or a whole navigation document.

Why are some rules reported but not fixed?

Because a repair needs judgement. Guessing a heading level or a link label can silently corrupt a book, so booklens reports those and leaves the decision to a human.

Can it run in CI and fail a pull request?

Yes. Audit exits 1 on any error-severity issue and can emit SARIF 2.1.0 for GitHub code scanning. --fail-on controls the threshold.

Does it handle other file formats?

No — booklens is EPUB only. Office, ODF, SVG, and web-archive formats are covered by its sibling tools, linked in the footer.
